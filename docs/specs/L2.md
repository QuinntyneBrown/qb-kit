# L2 - Detailed Requirements

## L2-001: Tool entry point
**Traces to:** L1-001

1. Given a locally packed and installed tool, when `qb-kit --help` runs, then it lists `new`.
2. Given an installed tool, when `qb-kit --version` runs, then it prints the package version.

## L2-002: Workspace naming
**Traces to:** L1-002

1. Given a valid lowercase kebab-case name, when `qb-kit new <name>` runs, then it creates `<cwd>/<name>`.
2. Given an interactive terminal and no name, when `qb-kit new` runs, then it prompts for a name.
3. Given noninteractive input and no name, when `qb-kit new` runs, then it exits with a usage error.

## L2-003: Angular application
**Traces to:** L1-002

1. Given a valid new name, when generation succeeds, then Angular 22 creates a workspace with an application under `projects/<name>/`, SCSS, routing, strict typing, standalone components, external templates/styles, and no SSR or Git initialization.
2. Given the workspace, when `npm run build` runs, then it succeeds.

## L2-004: Lint and formatting
**Traces to:** L1-003

1. Given a generated workspace, when `npm run lint` runs, then Angular TypeScript and templates are linted successfully.
2. Given a generated workspace, when `npm run format:check` runs, then Prettier reports no differences.
3. Given a formatting violation, when `npm run format:check` runs, then it exits nonzero.

## L2-005: Jest tests
**Traces to:** L1-003

1. Given a generated workspace, when `npm test` runs, then its starter Angular component test passes under Jest and jsdom.
2. Given a failing test, when `npm test` runs, then it exits nonzero.

## L2-006: Input and destination safety
**Traces to:** L1-004

1. Given an invalid or platform-reserved name, when `qb-kit new` runs, then it exits nonzero before creating files.
2. Given an existing destination, when `qb-kit new` runs, then it exits nonzero without modifying it.
3. Given a path with spaces in its parent, when `qb-kit new` runs, then it creates the requested workspace correctly.

## L2-007: Failure handling
**Traces to:** L1-004

1. Given missing Node/npm or an unsupported Node version, when generation starts, then it explains the prerequisite and exits nonzero.
2. Given a failed external step, when generation runs, then it names the step, exits nonzero, and leaves the partial workspace for inspection.
3. Given cancellation, when generation runs, then it stops the child process and exits nonzero.

## L2-008: Default counter component
**Traces to:** L1-005

1. Given a newly generated workspace, when the root application renders, then it displays a single counter component in place of the Angular starter page.
2. Given the counter component showing a count, when the increment button is clicked, then the displayed count increases by one.
3. Given the counter component showing a count, when the decrement button is clicked, then the displayed count decreases by one.
4. Given the counter component's styles, when inspected, then spacing, color, and sizing use shared CSS custom-property tokens and responsive techniques (fluid sizing, wrapping layout, touch-sized targets) instead of fixed, non-responsive values.
